Local LLM

Run big open-weight GGUF models on your own machine — CPU or GPU — behind a plain OpenAI-compatible HTTP API. No cloud, no accounts, no build step in this GUI.

llama.cpp under the hood Python stdlib only, no deps CPU-safe by default POST /v1/chat/completions
Install GitHub Repo

How it fits together

One idea underneath everything: a model file on disk becomes a live HTTP server, and every front end is just a client of that server.

1. Weights
GGUF file on disk
models/<name>/*.gguf — downloaded once, gitignored
→
2. Engine
llama-server (llama.cpp)
One process per model, OpenAI-compatible on a fixed port
→
3. Front end
This picker, or the CLI
POST /v1/chat/completions — same contract either way

Launch a model

Each button POSTs to the local picker_server.py backend, which shells out to gui/launch.sh <model>. That starts the model CPU-only via bin/start-model.sh <model> --cpu-only if it isn't already running, then opens the model's built-in chat webui in its own app-mode browser window. CPU loading is slow — give it a minute after the button reports “launching”.

Install

There's no packaged installer — this is the real, documented setup sequence from docs/TUTORIAL.md. Steps 3 and 4 are scripted; step 2 (the CUDA build of llama-server) is machine-specific and intentionally isn't, so it isn't scripted here either.

1Clone the repo
git clone https://github.com/coleman-sagil/local-llm.git
cd local-llm
2Build llama.cpp's llama-server

Vendored into llama.cpp/ and gitignored on purpose — it needs a CUDA build specific to your GPU/toolkit, so there's no single command that works across machines. Follow llama.cpp's own build docs and confirm the binary lands at: 

llama.cpp/build/bin/llama-server
3Download the models

Fetches all three GGUF targets (see the GGUF Models section below for exactly what this pulls):

./download_models.sh
4Launch the picker

The real front door — starts picker_server.py and opens this page in an app-mode browser window:

./gui/launch-picker.sh
